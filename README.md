# PixelForge

**A professional, Photoshop-class pixel art studio in your browser — built for humans *and* coding agents.**

PixelForge combines a full-featured pixel editor (layers, blend modes, animation, selections, dithering) with a complete HTTP API, an MCP server, and a browser automation bridge — so Claude Code, Codex, Cursor, Z Code or any script can create pixel art right alongside you.

![PixelForge editor](docs/screenshots/editor-hero.png)

*The editor running "Twilight Beacon" — a 64×64, 11-layer, 4-frame animated scene drawn entirely by an AI agent through the HTTP API (see [Agent-made art](#agent-made-art)).*

## Why PixelForge

| For artists | For agents |
|---|---|
| 12 tools, selections, layers, 11 blend modes | Full REST API — create, edit, read, export over HTTP |
| Frame-based animation with GIF export | MCP server for Claude Code / Z Code / MCP clients |
| Pixel-perfect strokes, X/Y mirror symmetry | `window.PixelForgeAPI` bridge for browser automation |
| Dithering brushes, retro palettes (PICO-8, Sweetie 16, …) | ASCII pixel readout — agents can "see" art as text |
| Runs at 60fps from low-end laptops to desktops | Same engine everywhere: agent art = hand-drawn art |

Everything is built around one document format (`.pxforge.json`) and one pixel engine. What an agent draws through the API behaves identically to what you draw by hand.

## Quickstart

Requires **Node.js 20+ or Bun 1.1+**.

```bash
# 1. install
bun install        # or: npm install

# 2. set up the project library database (SQLite, zero config)
bun run db:push    # or: npm run db:push

# 3. start the studio
bun run dev        # or: npm run dev
```

Open <http://localhost:3000> and start drawing.

Useful scripts:

| Script | What it does |
|---|---|
| `bun run dev` | Start the dev server on port 3000 |
| `bun run lint` | ESLint across the codebase |
| `bun run db:push` | Apply the Prisma schema to SQLite |
| `bun run build` / `bun run start` | Production build & serve |
| `bun run agent-art/generate-twilight-beacon.ts` | Regenerate the agent-made demo art |

## Mastering the app

### 1. The interface

```
┌──────────────────────────────────────────────────────────────┐
│ Menu bar (File · Edit · Image · Layer · View · Help)          │
├────┬─────────────────────────────────────────┬───────────────┤
│ T  │                                           │ Color picker  │
│ o  │                                           │ Palette       │
│ o  │              Canvas                       │ Layers        │
│ l  │         (zoom & pan with                  │ Frames        │
│ s  │          Space / scroll)                  │ (timeline)    │
├────┴─────────────────────────────────────────┴───────────────┤
│ Options bar (tool settings) · Status bar (size, frame, zoom)  │
└──────────────────────────────────────────────────────────────┘
```

- **Left rail** — the 12 tools. The **options bar** under the menu changes per tool (brush size/shape, dither pattern, opacity, tolerance, fills).
- **Right column** — color picker, the active palette, and the layer stack. Drag layers to reorder; click the eye to toggle visibility.
- **Bottom** — the animation timeline with frame thumbnails, playback controls, and per-frame duration.
- **Status bar** — canvas size, current frame, cursor coordinates, and zoom level at a glance.
- Press `Tab` to hide all panels for pure full-canvas drawing.

### 4. Layers and blend modes

Layers behave like Photoshop's: each has **visibility, opacity, alpha-lock and a blend mode**. Index 0 is the bottom. Blend modes include `normal`, `multiply`, `screen`, `overlay`, `darken`, `lighten`, `color-dodge`, `difference`, `hue`, `saturation`, `color`, `luminosity` — the same modes the API and MCP server expose, so agent-drawn glow layers (`screen`) composite exactly like hand-made ones.

Workflow habits worth stealing:

- **Background → midground → subject → light effects.** Draw skies and gradients on the bottom layer, silhouettes above, and put glows/beams on a top `screen` layer at 30–60% opacity.
- **Alpha-lock a shaded layer** to repaint colors without spilling over transparent pixels.
- `Ctrl+E` merges down when a layer is finished — keeps the stack readable.

### 5. Animation

- The timeline holds up to 64 frames (32 layers); every layer has its own cel per frame.
- Add frames in the timeline (copied or empty), set per-frame duration in ms, and press `Enter` to loop.
- Export as **animated GIF** or as a **PNG spritesheet** from `File > Export`.
- The API mirrors all of it: `frameAdd`, `frameDuration`, `setFps`, and per-frame command targeting — see the [bouncing-ball recipe](AGENTS.md#recipes).

### 6. Color and palettes

The palette panel ships with **Sweetie 16, PICO-8, Endesga 32, Game Boy DMG, AAP-16 and Vinik24**. Pick one before you start and discipline does the rest — limited palettes are the #1 reason pixel art looks "retro right". `X` swaps primary/secondary; the eyedropper (`I` or `Alt`) keeps you inside the palette.

### 7. Pro techniques

- **Pixel-perfect mode** (options bar) removes the jitter on 1px lines — essential for clean outlines.
- **Mirror X/Y symmetry** draws symmetric sprites (faces, ships, creatures) in half the time.
- **Dithering brushes** (`25%`, `50%`, `75%`, Bayer 4×4) fake gradients and texture in true retro style — band your skies instead of smoothing them.
- **Bulk pixel placement** is 200k-pixel `setPixels` batches via the API — agents build entire mountainscapes in one command.
- **Read your art as text**: `GET /api/pixel/projects/{id}/pixels?mode=ascii` renders the luminance grid — a second pair of eyes that never lies.

## Agent-made art

The flagship demo — **"Twilight Beacon"** (the GIF above) — was produced by the script in [`agent-art/generate-twilight-beacon.ts`](agent-art/generate-twilight-beacon.ts):

1. **Design** — the script composes 174 API commands (layer stack, banded gradient, seeded star noise, dithered reflections, screen-blended light cone, 4 animation frames).
2. **Create** — `POST /api/pixel/projects` persists it to the shared library.
3. **Self-review** — a vision model critiques the rendered PNG as an art director (it caught a real bug: glow drawn *beneath* the lighthouse layer).
4. **Iterate** — the script is refined, re-run, and patched in place via `POST .../commands`.
5. **Ship** — PNG + animated GIF export, deep-link into the editor: `/?project=<id>`.

Result after three critique rounds: **9/10, "publishable"** — with every step reproducible from one file.

## For coding agents and CLIs

Full reference in **[AGENTS.md](AGENTS.md)**. The short version:

**HTTP API** (curl, fetch, anything):

```bash
# stateless one-shot render
curl -s -X POST http://localhost:3000/api/pixel/render \
  -H 'Content-Type: application/json' \
  -d '{"width":8,"height":8,"scale":16,"commands":[
        {"op":"rect","from":[0,0],"to":[7,7],"outline":"gold","fill":"#7e2553"},
        {"op":"setPixel","x":3,"y":3,"color":"#fff1e8"}]}' -o art.png
```

**MCP server** (Claude Code, Z Code, any MCP client):

```bash
claude mcp add pixel-art -- bun run /path/to/pixelforge/mini-services/pixel-mcp/index.ts
```

**Browser bridge** (Playwright / Puppeteer / devtools):

```js
await page.evaluate(() => window.PixelForgeAPI.execute([
  { op: 'fillLayer', color: '#1a1c2c' },
  { op: 'ellipse', from: [4, 4], to: [11, 11], fill: '#ffcd75', outline: '#5d275d' },
]));
```

Three paths, one engine, one document format — and the library the API writes to is the same library you browse in `File > Open from Library`.

## Project structure

```
src/
├── app/
│   ├── page.tsx                  # the studio (single-page app)
│   └── api/pixel/                # REST API — projects, commands, render,
│                                 #   pixels, png, gif, palettes
├── components/pixel/
│   ├── PixelForge.tsx            # app shell
│   ├── CanvasStage.tsx           # canvas + input engine
│   ├── engine.ts                 # render loop (rAF, dirty-region redraw)
│   ├── store.ts                  # Zustand editor state
│   ├── algorithms.ts             # shared pixel algorithms (Bresenham, flood,
│   │                             #   dither, ellipse — used by UI *and* API)
│   ├── bridge.ts                 # window.PixelForgeAPI automation bridge
│   └── panels/                   # layers, color, palette, timeline
├── lib/pixel-server/             # server kernel: command engine, schemas,
│                                 #   compositing, PNG/GIF render, projects
├── mini-services/pixel-mcp/      # standalone MCP server (its own port)
└── prisma/schema.prisma          # SQLite library (projects)
agent-art/                        # reproducible agent-made artwork scripts
```

## Tech stack

**Next.js 16 (App Router) · TypeScript 5 · Tailwind CSS 4 · shadcn/ui · Zustand · Prisma + SQLite · sharp (PNG/GIF) · gifenc** — canvas rendering is hand-rolled with `requestAnimationFrame` scheduling and typed-array cels, so it stays smooth from low-end laptops to high-refresh desktops.
